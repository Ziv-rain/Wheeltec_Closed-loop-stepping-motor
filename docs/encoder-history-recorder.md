# 两层板 RAM 历史记录与导出

## 目标与边界

本版只增加数据记录、停车后导出和离线整理，不改任务 3–6 路由、PID 参数、
前馈参数、电机数据报、循迹算法、机械角度限制或运动学符号。历史预测融合暂未接入
实时控制；先收集并验证 10 组真车数据，再决定 50/100 ms 前视量的符号、权重和限幅。

## 为什么不在运行时吐数据

大数据流本身不会“压坏”板子，危险在于它的实现方式：

- 9600 baud 的板间串口发送一个 14 B AA55 帧约需 14.6 ms，行驶中连续发送会占用主循环；
- 如果在 5 ms/1 ms 中断里等待串口，会制造控制抖动和丢帧；
- 无界数组或循环覆盖可能与栈碰撞；
- 运行中擦写 Flash 有毫秒级停顿、寿命和断电一致性风险。

因此本版行驶中只向固定长度的静态 RAM 数组写入，不打印、不写 Flash。

## 容量与保护

| 位置 | 采样率 | 每条 | 条数 | 最长时间 | 静态 RAM |
| --- | ---: | ---: | ---: | ---: | ---: |
| 底板编码器/电机/灰度 | 20 Hz | 12 B | 1536 | 76.8 s | 18,432 B |
| 上层球位/PID/前馈/摆杆 | 20 Hz | 20 B | 768 | 38.4 s | 15,360 B |

任一缓冲区满后都会停止记录并在 `*_END` 中输出 `flags=1`，不会回绕覆盖。
RAM 数据在断电、复位或重新烧录后丢失。开始新一次任务会清除上一次未导出的记录。

## 十组数据的现场流程

1. 烧录上层工程和 `LowerBoard/2026-Basic-Control-Task456-EncoderLogger` 底板工程。
2. 正常选择任务并跑完一圈；运行期间不需要 USB 或无线模块。
3. 停车后保持两块板供电，将 USB-TTL 接到上层 UART0，终端设为 115200-8-N-1。
4. 在终端开启“保存接收内容/会话日志”，发送一次 `H`。
5. 等到同时看到 `BALLLOG_END` 和 `CARLOG_END`。底板链路是 9600 baud，满 1536 条时
   导出大约需要 1 分钟，期间不要断电或开始新任务。
6. 保存为 `run01.txt`，再跑下一组；重复到 `run10.txt`。

不建议把十圈完整记录同时放入 MSPM0G3507 的 32 KB SRAM；现在的“一圈一导出”是不影响
控制且不需要额外硬件的做法。

## 离线整理

```powershell
python tools\analyze_encoder_history.py run01.txt
```

十组合并计算中值前视轨迹：

```powershell
python tools\analyze_encoder_history.py run01.txt run02.txt run03.txt run04.txt run05.txt run06.txt run07.txt run08.txt run09.txt run10.txt --prefix ten-runs
```

会生成：

- `run01-samples.csv`：原始增量、里程、中值速度、加速度、50/100 ms 未来加速度以及同时刻球和摆杆状态；
- `run01-profile.csv`：按任务和 50 ms 相位聚合的中值轨迹，可在完成 10 组后用于评估历史前视。

当前脉冲比例仍沿用原代码的 `0.0002618 m/count`。因底板里程只计“行程脉冲”而非有符号
位置，倒车数据不能直接当作负速度。

## 新增 AA55 帧

- `0x40/0x05`：只在停车后请求底板导出；
- `0x43`：导出开始/结束元数据；
- `0x44`：运行号、样本号、底板时间戳；
- `0x45`：运行号、样本号、左/右脉冲增量；
- `0x46`：运行号、样本号、左/右 PWM、基础速度和循迹位图。

原有 `0x40`–`0x42` 的长度、CRC 和字段单位保持不变。
