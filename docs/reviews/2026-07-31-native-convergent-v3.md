## 发现的问题

### P1：缓存视觉帧在 200 Hz 下被重复当成新控制样本

当前视觉约 20 Hz，而 `MechBalance_Tick5ms()` 在每个 5 ms周期都用同一位置、
同一速度调用 PID，并把 `dt` 固定为 `0.005 s`。因此一个视觉样本会被重复
控制约十次，积分量与真实测量周期不一致，速度项也在帧间被重复施加。

V3 处理：仅在 `frame_id` 变化时更新位置、速度、预测和 P/I/D；5 ms周期只
负责超时、安全保护和角度斜率执行。

### P1：用大 Kp 和 `±10°` 同时处理静摩擦与滚动制动

当前 `Kp=3.0 deg/cm`，位置误差超过约 `3.3 cm` 后比例项就会长期顶到
`±10°`。这能推得动球，但在相机 EMA、双缓冲和机械惯性存在时会形成
正负大角度切换，符合现场约 `+8/-8 cm` 不衰减的现象。

V3 处理：滚动阶段使用本仓库历史保守值 `Kp=0.80`、当前 `Kd=0.50`、
当前 `Ki=0.02` 和 `±6°`；静止超过 0.30 s 才独立使用由本车实测得到的
`+3.2°/-5.2°` 脱困角。位移 0.10 cm、速度 0.25 cm/s 或 0.20 s 任一达到
就释放脱困，避免球已滚动后仍持续注入大角度能量。

### P1：当前多级滤波和执行延迟没有进入控制相位判断

MaixCAM 当前使用 `dual_buff=True`、位置 EMA `ALPHA=0.35`，MCU 又对速度
低通。若只对当前误差做 PD，制动通常晚于真实球状态。

V3 处理：用最多 3 个新帧和实际到达时间估速，速度旧值权重 0.50；位置项
使用 `velocity × 0.10 s` 的有界预测，最多前移 1 cm。远离目标或接近 1 cm
时完整使用 D，远距离朝目标运动时使用 35% 并线性渐入，避免远处完全早刹。

### P1：视觉丢失保持最后倾角会继续给球加速

当前 main 的视觉超时路径保持 `s_theta_cmd`。如果丢失发生在大倾角阶段，
小球仍会继续运动。

V3 处理：视觉明确丢失、低置信度、越出 `±9 cm` 或 200 ms无直接数据时，
以 `20°/s` 回到原车水平/车辆加速度前馈基准。`requested` 仍保持，连续两个
有效直接帧后自动恢复。

### P1：PID 请求语义和硬件安全语义需要分开

用户要求发送一次 `V` 后不因普通事件退出 PID，但这不能解释为 PWM 越界或
原 `CL_*` 故障后仍强行驱动。

V3 处理：普通视觉丢失和瞬时 PWM 缺失只抑制输出，不清除 `requested`；
`W` 才清除请求。`X`、PWM 真正越过 `105°～190°` 或 `CL_*` 故障走独立
锁存急停，保留请求状态但禁止输出，必须重新上电恢复。

### P2：参考项目的参数不能直接用于本车

参考项目是 70°基准的 ZDT 正绝对角机构，位置单位是像素，其 PID、20°～100°
范围、18°～26°脱困和 260 px/s² 制动模型都没有本车标定依据。

V3 处理：这些参数全部未进入代码。只采用状态分层、直测门控、条件积分、
制动渐入和安全优先级等算法结构。

## 部署方式

在 CCS 中复制现有构建配置为独立 `native-convergent-v3`：

1. 仅在新配置中排除 `Control/mech_balance.c`；
2. 加入 `native_v3_core.c` 和 `mech_balance_v3.c`；
3. 增加 V3、Control、Hardware include 路径；
4. 保持其他原车源文件、数据包和硬件参数不变；
5. 重新生成 SysConfig 并完成全量 Debug 构建。

上电回零后不会自动进入 PID。发送一次 `V` 后保持 PID 请求，`W` 暂停，
`X` 锁存急停。

## 剩余风险和实机注意

- 正/负脱困数据来自现有 `+3°/-5°` 记录，但仍需确认当前球、轨道和装车状态；
- MaixCAM 的双缓冲与 EMA 实际总延迟尚未用同步时间戳测量，0.10 s是有界初值；
- 当前 8 字节协议的 4 个保留字节保持不变，因此 MCU 无法知道真实采集时间；
- 完整 CCS 构建前不能称为可烧录发布版；
- 仓库 `releaseBranch` 尚未配置，不能自行合并或发布；
- 首次真机必须从 `±3 cm` 开始，确认方向和丢失回水平后再测 `+5→-5` 与 `±8`；
- 若调整参数，只允许每次一项、小步修改，并记录连续遥测。
