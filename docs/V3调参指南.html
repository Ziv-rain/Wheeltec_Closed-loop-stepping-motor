1. 系统架构与串口分工

控制链

视觉 60Hz ──→ UART2 ──→ ProtoRx ──→ NativeV3 状态机 ──→ correction ──┐
  (MaixCam)              (0x30帧)     ROLLING/BREAKAWAY/                 │
                                      SETTLED/VISION_HOLD               ├──→ 融合
                                                                        │
车轮编码器 ──→ UART1 ──→ SetAccel ──→ acceleration_base_angle() ──→ ff_base ─┘
 (主控9600)  (0x42帧)                                     (atan2(-a,g))
                                                                        │
                                                              target = ff + correction
                                                                        │
                                                              CL_SetTargetAngle → 电机

三个串口

串口引脚波特率用途
UART0PA28(TX)/PA31(RX)115200🛠️ 调参命令(ASCII文本+回车)
UART1PA17(TX)/PA18(RX)9600主控 AA55 协议(0x40命令/0x41状态/0x42编码器)
UART2PA21(TX)/PA22(RX)115200视觉数据(0x30球位置/0x31触摸目标)
⚠️ 调参命令只发 UART0! 发到 UART1 会被当无效帧丢弃。UART0 用 ASCII 文本,不是 HEX。

2. V3 调参哲学(与旧版根本区别)

旧版(单环PID)V3(状态机)
位置增益KP=3.0 高增益硬推KP=0.80 低增益
静摩擦靠高KP硬突破BREAKAWAY 脱困:+3.2°/-5.2° 大角度冲一下,球一动就卸力
球稳定PID 持续微调(可能抖)SETTLED 锁定:输出归零,不抖不耗
视觉丢失保持最后角度(球继续跑)20°/s 缓回水平,球不乱跑
帧率处理5ms 重复算同一帧(积分虚增)新帧才算,5ms只做安全检查
车体扰动无补偿,球先跑PID再追加速度前馈:提前倾角抵消惯性
💡 核心思维转变: 旧版调参是"调大KP直到能推动,再调KD压振荡"。 V3 是"增益保持低,让状态机去做重活"——推不动找脱困角度,稳定后找锁定阈值,车动了找前馈增益。

4. 第一阶段:纯 V3 状态机调参(F0)

先发 F0 关前馈! 把"车体扰动"和"球控制"分开调,一次只解决一个问题。

4.1 前置条件检查

  1. 上电 → LED 亮 → 电机回零完成(摆杆水平)
  2. 视觉摄像头开着(60Hz 发数据)
  3. S → valid=1(视觉数据进来了)
  4. F0 回车 → OK FF merge OFF
  5. V 回车 → Vision PID started

4.2 调 KP(位置增益)

1
初始 KP=0.80,球放 +3cm
发 S 观察球回中过程(目标: 3~5秒回到目标附近)
2
回得太慢 → 增大 J 1.2
每档 +0.2~0.3,重新观察。回中时间应缩短到 2~3 秒
3
过冲振荡 → 减小 J 0.6
球冲过目标来回荡 → 减小 KP(不是增大 KD!)先降 KP 到不过冲
4
目标: 无过冲 + 回中快
KP 定在 0.8~1.2 之间一个"快速且不过冲"的值

4.3 调 KD(阻尼)

  1. KP 定好后,球在目标附近来回小幅荡
  2. 增大 M 0.6 ~ 0.7 压振荡
  3. KD 太大 → 球迟钝、回中慢(这时往回降)
  4. 注意: V3 的 D 项是距离自适应的(近 1cm 全开,远 3cm 只 35%),这是特性

4.4 验证脱困(BREAKAWAY)

脱困是 V3 解决静摩擦的机制: 球静止在误差≥0.35cm 处持续 300ms → 状态机输出强制 +3.2°(正侧)或 -5.2°(负侧)冲一下 → 球一动(≥0.25cm/s 或位移 0.1cm)立即恢复 ROLLING。
  1. 把球放在离目标 1cm 处,等它完全静止
  2. 静止 300ms 后应看到电机突然冲一下 → 球开始滚 → 回到目标
  3. 如果脱困推不动: 改代码 breakaway_positive_deg / negative_deg(见第 6 节),+0.3° 一档
  4. 如果脱困太猛球飞过: 减脱困角度或减 breakaway_max_ms

4.5 验证锁定(SETTLED)

  1. 球稳定在目标 ±0.3cm 且速度 <0.6cm/s 持续 500ms → 进入 SETTLED
  2. 现象: S 的 out 归零,电机不再动(不抖不耗)
  3. 球被碰出 0.6cm 或速度超 1.2cm/s → 退出锁定恢复控制
  4. 如果锁定后球又慢慢溜走 → 轨道不水平 → 调 T(下一节)

4.6 调 trim(静态补偿)

  1. 球稳定在目标后,观察它是否始终偏向一侧(轨道微倾/摩擦不对称)
  2. 球持续偏正侧 → T -0.3(负trim抵消)
  3. 球持续偏负侧 → T +0.3
  4. 每次 ±0.1~0.3,调到球能停在目标正中央

5. 第二阶段:前馈融合调参(F1)

5.1 开启并验证

  1. F1 → OK FF merge ON
  2. S → merged=1,静止时 ff≈trim(≈0)
  3. 推一下车 → ax 变化 → ff 跟随变化 ✓ 前馈在工作

5.2 前馈物理原理

小车加速 a_x 时,球受到"虚拟重力" -a_x(惯性力)

需要的补偿倾角:  θ_ff = atan2(-gain·a_x, g) × 57.3°

  小车加速前进 → 摆杆前倾(抵消球向后滚的惯性)
  小车刹车     → 摆杆后倾(抵消球向前冲的惯性)

5.3 调前进增益 G

现象调整
加速时球往后滚(补偿不足)G 1.2 ~ 1.5
加速时球往前冲(过度补偿)G 0.7 ~ 0.8
加速时球稳定不动✅ G 合适

5.4 调刹车增益 B

现象调整
刹车时球往前冲(没刹住)B 1.2 ~ 1.5
刹车时球往后滚(过补偿)B 0.7 ~ 0.8
💡 经验: 前进和刹车通常不对称(刹车更急),B 往往需要比 G 大。 你的机械标定也证明了这点:正侧 3°/cm,负侧 5°/cm。

5.5 调速率限制 L

  1. 默认 80°/s(电机角度变化最快速度)
  2. 电机动作太猛/机构冲击 → L 40 ~ 60
  3. 动作太慢跟不上 → L 80
  4. 视觉丢失回水平的速度固定 20°/s(独立,不随 L 变)

5.6 手动测试前馈 A

没有车轮编码器数据时,可用 A <值> 手动注入加速度,验证前馈方向和强度: 
A 1.0   → 模拟 1 m/s² 前进加速度 → S 看 ff 变化
A -1.0  → 模拟 1 m/s² 刹车 → ff 反向变化
A 0     → 恢复

6. V3 内部参数(改代码)

这些参数在 Control/native_v3_core.c 的 NativeV3_DefaultConfig() 里,改完需重新编译。

🔴 脱困参数(最常调)

参数默认说明
breakaway_positive_deg+3.2°球在正侧(误差>0)脱困角度。推不动就 +0.3
breakaway_negative_deg-5.2°球在负侧(误差<0)脱困角度。负侧更费力,通常要更大
stiction_error_cm0.35 cm误差超过此值且静止 → 触发脱困
stiction_confirm_ms300 ms静止多久才确认脱困(太短易误触发)
breakaway_max_ms200 ms脱困最长时间(超时强制恢复)

🟡 锁定参数

参数默认说明
settled_position_cm0.30 cm误差 <此值 且 速度 <0.6 → 开始计时锁定
settled_exit_position_cm0.60 cm误差 >此值 → 退出锁定(滞回防抖)
settled_confirm_ms500 ms稳定多久进入锁定

🟢 预测与制动

参数默认说明
prediction_s0.10 s位置预测时间(超前量)
prediction_limit_cm1.0 cm预测上限(防噪声放大)
brake_near_cm1.0 cm距目标 <1cm → D项全开(100%)
brake_far_cm3.0 cm距目标 >3cm → D项 35%

🔵 视觉与积分

参数默认说明
vision_timeout_ms200 ms视觉超时 → 回水平
recovery_frames2视觉恢复需连续 2 帧(防抖动)
minimum_confidence40置信度下限(低于拒帧)
integral_position_cm1.0 cm误差 <1cm 才允许积分
integral_velocity_cm_s1.0 cm/s速度 <1cm/s 才允许积分

7. 完整调参流程(从零开始)

📋 调参记录表模板

日期: ______  场地: ______  光照: ______  轨道: ______

阶段一(F0 纯V3):
  KP = ______  (起始0.80)     现象: 快/慢/振荡
  KD = ______  (起始0.50)     现象: 荡/钝
  脱困角度 = +____ / -____    现象: 推得动/推不动
  trim = ______               现象: 偏向正/负侧
  结论: 球能稳定在目标, 不荡, 能脱困 ✓

阶段二(F1 前馈):
  G (前进) = ______           现象: 加速球向后/前/稳
  B (刹车) = ______           现象: 刹车球向前/后/稳
  L (速率) = ______           现象: 动作猛/钝
  结论: 推车球不乱跑 ✓

最终确认:
  球 +3cm 放下 → 回中时间 ____s  过冲 ____cm
  球 -3cm 放下 → 回中时间 ____s  过冲 ____cm
  静止 1cm 处 → 脱困成功? 是/否
  推车 0.5m/s 急停 → 球位移 ____cm

操作序列

  1. 上电 → 等回零 → F0 → V
  2. 调 KP → 调 KD → 验证脱困 → 调 trim
  3. W 停止 → F1 → V 重启
  4. 调 G/B → 验证推车
  5. 把最终值写回 demo_config.h 或 NativeV3_DefaultConfig,重新编译固化
⚠️ 一次只改一个参数! 每次改动后记录现象,再改下一个。同时改多个参数会导致不知道是哪个引起的。

9. 赛前检查清单

  1. ☐ 摆杆水平时 PWM 值已写入 PWM_HORIZONTAL_REF
  2. ☐ 视觉标定准确(S 的 ball 与实际位置对比)
  3. ☐ V3 参数已固化(不是依赖串口临时调)
  4. ☐ 前馈增益 G/B 已固化,推车验证过
  5. ☐ UART1 9600 与主控通信正常(S 能看到状态帧)
  6. ☐ 编码器 TYPE 0x42 数据正常(S 的 ax 有值)
  7. ☐ 脱困测试通过(球静止 1cm 处能自己回来)
  8. ☐ 灯光环境稳定(视觉检测稳定)
  9. ☐ 备用电池/供电充足
