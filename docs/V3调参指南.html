1. 系统架构与串口分工

控制链

视觉 60Hz ──-> UART2 ──-> ProtoRx ──-> NativeV3 状态机 ──-> correction ──┐
  (MaixCam)              (0x30帧)     ROLLING/BREAKAWAY/                 │
                                      SETTLED/VISION_HOLD               ├──-> 融合
                                                                        │
车轮编码器 ──-> UART1 ──-> SetAccel ──-> acceleration_base_angle() ──-> ff_base ─┘
 (主控9600)  (0x42帧)                                     (atan2(-a,g))
                                                                        │
                                         target = ff_base + correction (F1)
                                                 trim + correction      (F0)
                                                                        │
                                              CL_SetTargetAngle -> 电机

三个串口

串口引脚波特率用途
UART0PA28(TX)/PA31(RX)115200🛠️ 调参命令(ASCII文本+回车) + 自动S输出(500ms)
UART1PA17(TX)/PA18(RX)9600主控 AA55 协议(0x40命令/0x41状态/0x42编码器)
UART2PA21(TX)/PA22(RX)115200视觉数据(0x30球位置/0x31触摸目标)
⚠️ 调参命令只发 UART0! 发到 UART1 会被当无效帧丢弃。UART0 用 ASCII 文本(不是 HEX),命令以回车结尾。

2. V3 调参哲学

旧版(单环PID)V3(状态机)
位置增益KP=3.0~5.0 高增益硬推KP=0.8~1.5 低增益
静摩擦靠高KP硬突破(易振荡)BREAKAWAY 脱困:卡住300ms全力6°冲,球一动就释放
球稳定PID 持续微调(可能抖)SETTLED 锁定:±0.5cm内输出归零,不抖不耗
视觉丢失保持最后角度(球继续跑)20°/s 缓回水平,球不乱跑
帧率处理5ms 重复算同一帧(积分虚增)新帧才算,5ms只做安全检查
车体扰动无补偿加速度前馈:提前倾角抵消惯性
💡 核心思维: 不要靠高 KP 硬推。KP 低一点 + 脱困机制 = 推得动且不振荡。 前馈和 PID 是叠加关系:前馈预判车体惯性,PID 纠正球位置偏差。

5. 第一阶段:调球控制(纯 V3, F0)

先 F0 关前馈! 把"车体扰动"和"球控制"分开调,一次只解决一个问题。

5.1 前置检查

  1. 上电 -> LED 亮 -> 电机回零完成(摆杆水平)
  2. 视觉摄像头开着(60Hz 发数据)
  3. S -> valid=1(视觉数据进来了)
  4. F0 -> OK FF merge OFF
  5. V -> Vision PID started(act 变 1)

5.2 调 KP(位置增益)

球放 +3cm,观察回中过程:

现象调整原因
球快速回中,不过冲✅ KP 合适-
球回得太慢J 1.2 ~ J 1.5KP 太低
球冲过目标振荡J 0.6KP 太高
球卡在远处推不动靠脱困机制,不调KP脱困6°会冲
关键: V3 有脱困机制(卡住300ms全力6°),所以"推不动"不再靠高KP解决。 KP 保持低(0.8~1.5),让脱困做重活。

5.3 调 KD(阻尼)

  1. KP 定好后,球在目标附近来回小幅荡
  2. 增大 M 0.6 ~ 0.7 压振荡
  3. KD 太大 -> 球迟钝、回中慢 -> 往回降

5.4 验证脱困(BREAKAWAY)

  1. 球放在离目标 2~3cm 处,等它完全静止
  2. 静止 300ms 后应看到电机突然冲一下(6°) -> 球开始滚
  3. 球一动(≥0.4cm/s) -> 立即回 ROLLING -> PID 接管
  4. 6° 还推不动 -> 检查轨道是否有不平/卡点

5.5 验证锁定(SETTLED)

  1. 球稳定在目标 ±0.5cm 且速度 <0.6cm/s 持续 500ms
  2. 现象: S 的 out 归零,电机不再动(不抖不耗)
  3. 球被碰出 0.8cm -> 退出锁定恢复控制

5.6 调 trim(静态补偿)

  1. 球稳定后观察是否偏向一侧(轨道微倾)
  2. 偏正侧 -> T -0.3;偏负侧 -> T +0.3
第一阶段目标: 球能从任意位置回中,锁定不抖,脱困能推动。

6. 第二阶段:调前馈(F1, A 命令法)

💡 用 A 命令调前馈,不用启动小车!
A 命令注入恒定已知加速度,排除编码器噪声,精确验证 G 和 E 的效果。

6.1 开启并验证方向

F1       ← 开前馈融合
V        ← 启动(act=1, 前馈才参与)
A 1      ← 模拟车加速 1 m/s²
S        ← 观察:
           ax=1.00  ← 加速度进来了
           ff=-5.7  ← 前馈角度(负=后倾, 推球向前抵消惯性) ✓
           球往负方向滚 ← 前馈在作用
A 0      ← 复位, ff 回 0
方向检查:
A 1(正加速) -> ff 应为负(摆杆后倾)
A -1(刹车) -> ff 应为正(摆杆前倾)
方向反了 -> 前馈帮倒忙,需查符号(告诉我)

6.2 调 G(增益 = 斜率)

G 控制"加速度->倾角"的斜率。A 命令注入已知值,看 ff 是否匹配:

A 命令G=1.0 期望 ffG=1.5 期望 ff说明
A 0.5-2.9°-4.3°小加速
A 1.0-5.7°-8.5°中加速
A 2.0-11.3°-16.7°大加速
A 3.0-16.4°-23.8°极限(过滤边界)
A 1 -> S 看 ff:
  ff=-5.7  -> G 合适 ✓
  ff=-3.0  -> G 太小, 调 G 1.5
  ff=-8.5  -> G 太大, 调 G 0.7
A 0       ← 复位

6.3 调 E(限幅 = 上限)

E 只在 ff 打满时才有用。调大 G 到 ff 打满后,只能调 E:

E 30     ← 当前默认(限幅30°)
A 3      ← 注入大加速度
S        ← ff 应显示 -30.00(打满)
E 20     ← 收紧限幅
S        ← ff 变 -20.00
A 0      ← 复位

6.4 G 和 E 的关系(关键!)

ff = atan2(-G × ax, g) × 57.3°  然后限幅到 ±E

情况1: ff 未打满(|ff| < E)
  -> 调 G 有效(斜率), 调 E 无效(没到上限)

情况2: ff 打满(|ff| = E)
  -> 调 G 无效(被钳住), 调 E 有效(抬高上限)

判断方法: S 看 ff
  ff=-5.7  (未打满) -> 调 G
  ff=-30.0 (打满)   -> 调 E

6.5 调刹车增益 B

A -1     ← 模拟刹车(负加速度)
S        ← ff 应为正值(前倾)
B 1.5    ← 刹车增益加大
A -1
S        ← ff 应更大
A 0      ← 复位
第二阶段目标: A 命令验证前馈方向对、G/E 参数合理,ff 跟随 ax 变化。

7. 第三阶段:实战验证(小车启动)

A 命令调好后,用真实小车验证动态效果:

7.1 接入主控编码器

F1 -> V -> 小车启动 -> S 观察:
  ax= 平滑变化(真实加速度)   ← 应在 0~2 之间
  ff= 跟随 ax 变化            ← 前馈在工作
  ball= 球位移                ← 应 ≤2cm

车停下:
  ax=0 -> ff=0 -> 球回中锁定

7.2 诊断:ax 恒 0(数据没来)

检查项方法
主控连接UART1 9600, 串口助手看 0x42 帧
编码器数据0x42 帧的 left/right 是否变化
过滤是否过严ax>3 被丢弃(检查真实加速度是否超3)
断流超时500ms 无帧 -> 前馈衰减回零

7.3 诊断:球位移大(补偿不足)

现象原因解决
ax 有值但 ff 打满限幅不够E 调大
ff 未打满但球还跑增益不够G 调大
ax 跳变大(噪声)编码器回绕/噪声检查主控端编码器
加速时球往后走补偿不足G 调大 或 E 调大
加速时球往前冲补偿过头G 调小
加速度要求: 给主控的要求是小车加速度 ≤2 m/s² 且渐变(不要突跳)。 如果主控加速太猛(>3 m/s²),前馈被过滤丢弃,球会跑。
第三阶段目标: 小车启动/刹车时球位移 ≤2cm,停车后 2~3 秒回中锁定。

8. 常见问题排查

现象原因解决
上电 LED 不亮.o 缓存 / 烧录失败CCS Clean + Build,重新烧录
S 显示 valid=0视觉没连/没开检查 UART2 接线 + MaixCam 启动
S 显示 ax=0 恒定主控/编码器没数据检查 UART1 9600, 0x42 帧
ff 恒 0 但 ax≠0固件旧 或 待机(act=0)先 V 启动; 仍0则重新烧录

球稳定但慢慢溜走轨道不水平调 T trim

9. 赛前检查清单

  1. ☐ 回零正常(PWM≈135.21°,摆杆水平)
  2. ☐ 视觉有效(S 显示 valid=1,ball 与实际位置吻合)
  3. ☐ 球控制稳定(球放 3cm 能回中锁定,不振荡)
  4. ☐ 脱困有效(球卡 2cm 静止 300ms 后能冲开)
  5. ☐ 前馈方向正确(A 1 -> ff 负,球往负滚)
  6. ☐ 前馈参数已固化(G/B/E 写回代码)
  7. ☐ 主控通信正常(UART1 9600, ax 有值)
  8. ☐ 推车验证通过(球位移 ≤2cm)
  9. ☐ 赛题流程联调(select->start->stop)
