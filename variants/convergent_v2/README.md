# Ball-and-Beam 收敛控制 V2

本目录是一套独立试验版本。它没有替换或修改仓库中的
`Control/mech_balance.*`、`Control/ball_control.*`、`Hardware/proto_rx.*`
或 MaixCAM原程序。

## 要解决的现象

现有视觉精调参数为 `Kp=0.50 deg/cm`、正常输出限幅 `±1.5°`。忽略速度项时，
位置误差超过约 `3 cm`输出就已饱和。小球在 `+8 cm`与 `-8 cm`之间运动时，
控制器大部分时间因此退化为延迟后的正反满幅切换。

MaixCAM每50 ms最多发送一帧，原速度低通约再增加一帧相位滞后，旧控制器的
正常反馈使用延迟位置；`-5°`单向强制制动又远大于 `±1.5°`精调角，容易产生
持续极限环。

V2不再把位置误差直接放大为摆杆角度，而使用以下结构：

```text
20 Hz位置 + 推理耗时
        ↓
延迟状态校正 + 历史角度重放 → 估计当前 x、v
        ↓
位置外环 → 限速/限加速度的 v_ref
        ↓
参考加速度前馈 + 速度反馈 + 条件积分
        ↓
对称预测制动 + 角度/角速度限制
        ↓
原有5 ms步进电机角度闭环
```

控制符号沿用实机结论：目标角为正时，小球位置向负方向运动。

## 初始参数来源

V2保留旧工程已经过实机确认的方向和安全边界：

- `CL_PERIOD_MS=5 ms`；
- PWM硬范围 `105°..190°`、保护余量 `2°`；
- 水平PWM参考 `143°`；
- 视觉位置有效范围 `±9 cm`；
- 正常精调角度仍为 `±1.5°`。

旧控制曾按 `-5°`制动约等效 `12 cm/s²`减速度估算，因此V2初始模型取
`Ktheta=2.4 cm/s²/deg`。该值仅用于受限前馈和预测，并以极慢速率在
`1.2..6.0 cm/s²/deg`内估计；即使模型不准，前馈仍被限制在 `±0.6°`。

V2独立初值：

| 参数 | 初值 | 与旧值的关系 |
|---|---:|---|
| 位置到目标速度 | `0.35 1/s` | 旧回程为 `1.0 1/s` |
| 最大目标速度 | `2.5 cm/s` | 旧回程为 `5 cm/s` |
| 最大参考加速度 | `2.0 cm/s²` | 新增S形参考限制 |
| 速度反馈 | `0.55 deg/(cm/s)` | 位于旧精调0.40与回程0.80之间 |
| 正常角度 | `±1.5°` | 不变 |
| 对称制动角 | `±2.0°` | 代替旧单向 `-5°`跳变 |
| 近点积分 | `0.03` | 旧值0.08，仅在误差≤1 cm时启用 |
| 输出变化率 | `20 deg/s` | V2外环独立保守限制 |

这些值优先保证收敛，不追求第一次就快速冲到目标。不得一次大幅提高速度、
角度和位置增益。

## V2视觉帧

帧头、CRC、TYPE和长度均与旧协议相同：

```text
AA 55 30 08 [position:int16] [confidence:u8] [status:u8]
               [frame_seq:u16] [capture_to_send_ms:u16] [CRC16]
```

最后4字节原来是填零的保留区。旧主控仍可忽略；V2用它们区分新帧，并把
测量校正到采集时刻后，根据历史实际摆杆角重新预测到当前5 ms控制时刻。

`detect_ai_v2.py`保持原来的像素中心、比例、模型和置信度阈值。它关闭隐藏的
双缓冲流水线以降低一帧延迟，并在屏幕显示实际推理耗时。若实测FPS低于20，
应先恢复双缓冲并记录新增延迟，不能直接提高控制增益。

## V锁定和安全语义

- `BBV2_Start()`：相当于V，置位持续控制请求；
- `BBV2_Pause()`：相当于W，是正常清除请求的接口；
- 视觉超过150 ms无有效帧：请求仍保持，输出按20 deg/s缓回水平；
- 连续收到2个有效新帧后自动恢复控制，第一帧不直接产生大微分；
- PWM信号暂时无效：禁止输出但保留请求，信号恢复后重新接管；
- PWM触及硬限位、角度闭环拒绝目标或X急停：停止执行，绝不绕过或自动清故障；
- 急停不会伪装成正常暂停，恢复必须重新初始化控制器/重新上电。

## 独立构建接入

不要直接覆盖旧源文件。建议在CCS中新建一个V2 Build Configuration：

1. 添加 `mspm0/ball_beam_v2.c`、`ball_beam_v2_runtime.c`和
   `proto_rx_v2.c`，加入本目录include路径；
2. 根据 `app_demo_v2_example.c`创建V2入口；旧控制器可以继续留在工程，
   但同一5 ms周期只能有一个模块向 `CL_SetTargetAngle()`写目标；
3. UART2中断收到的每个字节调用 `BBV2_Example_ProcessVisionByte()`；
4. 自动回零完成后，每5 ms调用 `BBV2_Example_Tick5ms()`，再运行原有
   `CL_Process()`；
5. UART0将V/W/X/N分别映射到示例中的Start/Pause/Emergency/SetTarget；
6. MaixCAM另装 `maixcam/` V2应用，先观察HUD中的 `proc`和实际FPS。

当前仓库没有指定发布/烧录分支，因此本目录不能直接视为可烧录发布版本。

## 仿真和语法检查

```powershell
python variants/convergent_v2/simulation/ball_beam_v2_model.py --sweep
```

模型扫描机构增益 `1.2/2.4/6.0 cm/s²/deg`和视觉延迟
`50/100/150 ms`。初始位置为 `+8 cm`、目标为0，所有组合保持在±9 cm内；
12秒后的振幅约 `0.13..0.31 cm`。这些结果用于排除明显不收敛结构，不能替代
实机摩擦、轨道倾斜、回差和视觉误检测试。

## 首次实机步骤

1. 无球运行旧自动回零，确认水平PWM仍为143°附近；
2. V2不放球，只测试 `V → W → X`状态和回水平，确认急停可用；
3. 把目标设为0，从 `+3 cm`开始，观察估计位置、速度、角度和延迟；
4. 再测试 `+5 cm`，确认控制输出符号为正且小球向负方向运动；
5. 最后测试 `+8 cm → 0`及 `+5 cm → -5 cm`，每种至少10次；
6. 记录最大正负位置、首次过零速度、最终误差、`proc/delay/Ktheta`。

若仍低频摆动，第一步只把 `position_to_speed_per_s`从0.35降到0.30；
若到点仍有较大速度，再把速度反馈从0.55小幅增到0.60。一次只改一个值，
不允许同时放大角度、速度和增益。
